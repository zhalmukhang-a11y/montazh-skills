# Айнур — рилс из интервью

Пользователь не программист, пишет по-казахски. Отвечай на его языке, коротко, код не показывай. **Всегда сначала превью на проверку (720p), потом финальный рендер только после «ок».**

## Подготовка
1. Скопируй `template/` в `work/<проект>/` (`cp -rn`), исходник положи/ссылкой в `media/raw.mp4`, референс в `ref/ref.mov` (для музыки).
2. `npm install`. Python: `faster-whisper numpy opencv-python-headless`; для музыки — venv `.venv` с `torch torchaudio` (CPU) и `demucs`.
3. Chrome: `/usr/bin/google-chrome`.

## Как работать
1. **Текст.** Пользователь присылает точный текст (субтитр) и заголовок. Субтитры — только его текст, дословно. Если просит прислать текст ролика — отдай текстом, без кода.
2. **Найти время.** `faster-whisper large-v3-turbo` по нужному куску (`language=kk`, `word_timestamps=True`, `condition_on_previous_text=False`, initial_prompt = первая фраза текста). Тайминги Whisper по казахскому неточные — проверяй по громкости.
3. **План** `work/planXX.py` (пример `work/example_plan.py`):
   - `SPANS` — куски исходника (сек), которые берём; вопросы ведущего и лишние фразы не включать.
   - `FILL` — что вырезать внутри: «ааа/эээ/ммм», повторы, лишние слова («Ол жерде», «бізде», двойное «артқы» и т.п.).
   - `FIX` — (начало, конец, «текст пользователя») по предложениям: слова субтитров раскладываются по реальному времени речи.
   - `GRADE='null'` — без фильтра (исходник). Иначе берётся `grade.txt` (подгон под референс).
4. **«Ааа/эээ/ммм» — главная боль.** Whisper их НЕ пишет, растягивает соседнее слово. Ищи так:
   - подозрительно длинные слова (>0,8 с) в выводе Whisper;
   - профиль громкости/спектра окнами 50 мс (`scripts/fillers.py` + ручной профиль): «эээ/ммм» = ровный гул −30…−45 дБ с низким спектральным потоком (≈0,7–1,0) длиной ≥0,25 с; паузы = ниже −42 дБ;
   - короткое окно Whisper с подсказкой «Ээ, ммм» лишь подсказка (подсказка сама галлюцинирует) — решай по громкости.
   - Повторы/дубли («Лимфа… жасамады ма, … бұлшықет жасамайды. Бұлшықет жасамады ма») — режь, оставляя версию ближе к тексту.
   - Проверь, не срезался конец фразы (было: «жұмыс жасамайды» на стыке) — после нарезки транскрибируй `work/cut.mp4` ещё раз и сверь с текстом.
5. **Нарезка:** `python3 scripts/cut_gen.py planXX` → `work/cut.mp4`, `work/subs.json` (по 1 слову, строчные, без знаков), `work/toks.json` (время каждого слова в ролике), `work/pieces.json`. Паузы < −42 дБ от 0,15 с режутся сами. Крупность чередуется по предложениям: общий 1.15 / крупный 1.45, стол внизу виден.
6. **Кожа.** По умолчанию почти без обработки: `scripts/beauty.py cut.mp4 cut_beauty.mp4 0 0.12 0 0 0 0` («1% сглаживания»). Не осветлять лицо — пользователь просил «как исходник/референс». Сильная версия (если попросят): `0.25 0.85 0.3 0.4 0.5 0.4`. Стол из маски исключён.
7. **Титры** `work/titles.json` (пример `work/example_titles.json`):
   - Первый — заголовок пользователя: капс + рукописная строка. Пишем ровно как он написал; длинный капс можно разбить на 2 строки словом `"/"`. Держится только пока звучит первая фраза/вопрос.
   - Дальше — ключевые слова по тексту (причины, термины): капс 1–2 слова в момент произнесения + короткая рукописная подпись. Слова появляются из размытия с лёгким зумом (scale 1.18→1).
8. **Звуки:** на каждое слово титра тихий «вжух», на рукописную строку тихий «дзынь» — `scripts/sfx.py events.json <длительность> sfx.wav`. Громкость: вжух 0.03, дзынь 0.015 (пользователь дважды просил тише).
9. **Вставки** `work/inserts.json` 1,5 с под конкретные слова, бесплатный сток Mixkit (`scripts/mixkit.sh <id> <имя>`; поиск `https://mixkit.co/free-stock-video/<запрос>/`). Строго по теме слова: ребёнок, а не балерина; руки, держащие стопу ребёнка — для «анамнез/осмотр». Не ставить вставку под заголовок-хук (светлый фон съедает рукописную строку). Pexels/Pixabay из облака закрыты; Higgsfield платный — сначала спросить и показать цену.
10. **Музыка:** `scripts/music.sh ref/ref.mov work/bg.mp4 work/bg_music.mov` (громкость как в референсе). Затем смешать с `sfx.wav` и `scripts/finalize.sh` → 1080×1920, 30 fps, 14 Мбит/с, −14 LUFS.
11. **Сдать:** превью 720p в чат → правки → «ок» → полный файл в чат и в `output/` репозитория. Файл >90 МБ пережать (`-crf 20 -preset slow`, звук aac 160k) — лимит GitHub 100 МБ.

## Правила
- Только слова из текста пользователя; лишние слова, повторы, паузы, «ааа/эээ/ммм» вырезать.
- Смысл и порядок не менять.
- Исходники не трогать; работа в `work/`, видео в git только из `output/`.
- Не запускать два рендера одновременно; длинный ролик (70 с) с ретушью собирается ~40 мин — предупреждай, сколько осталось.
