# Айнур — рилс «тёплая студия»

Пользователь не программист: пиши по-казахски/по-русски (как он), коротко, код не показывай. Экономь токены: меньше проверок, кадры смотри одним листом.

## Подготовка (один раз в сессии)
1. Папка проекта `work/<имя>/`: скопируй туда `template/` (`cp -rn`), создай `media/ work/ out/ broll/`. Исходник — ссылкой: `ln -sf <путь к видео> media/src.mp4`.
2. `npm install`. Python-пакеты в облаке уже стоят (faster-whisper, numpy). Chrome: `/usr/bin/google-chrome`.
3. Видео с Google Drive: `gdown "<ID>" -O input/` (если `--fuzzy` не работает — передавай только ID).

## Этапы (так делались ролики «Астигматизмнің 4 себебі», «Гарантия бересіз бе?», «Кесар vs табиғи босану»)
1. **Слова.** `python3 -I scripts/transcribe_whisper.py media/src.mp4 kk > work/words.json` (20 мин видео ≈ 15 мин на процессоре). Длинное интервью — сначала раздели на темы, каждая тема = один рилс с законченной мыслью.
2. **Текст пользователя — закон.** Пользователь присылает текст рилса и заголовок. Сопоставь его фразы с номерами слов: оставляй только то, что есть в тексте; вырезай слова, которых в тексте нет («бұл жерде», «деген секілді», повторы, «болуы мүмкін», если их нет), «ээ/ммм» и паузы. Распознавание путает казахский — сверяй по смыслу и по времени, а не по буквам.
3. **Голос интервьюера.** `python3 -I scripts/voices.py media/src.mp4 work/words.json <от> <до>` — слова с пометкой «М» (низкий голос <130 Гц) — это мужчина-интервьюер, вырезать. Если его вопрос есть в тексте пользователя — всё равно режь звук и скажи об этом.
3а. **«ээ/ааа» внутри слов.** Распознавание часто «приклеивает» запинку к слову (слово длится 1–2,5 с). Найди такие места:
   - `python3 -I scripts/fillers.py media/src.mp4 work/words.json <от> <до>` — непрерывный ровный звук ≥0,3 с;
   - сравни с вторым проходом распознавания (whisper с подсказкой «Ээ... ммм») — дыры ≥0,25 с внутри длинного слова, слова-паразиты «уже, жаңағы»;
   - режь только целые слова-паразиты («жаңағы»=«жағы», куски без смысла); короткие связки «яғни», «бізде», «түрлі» внутри фразы НЕ вырезай — получаются рывки и «съеденные» слова;
   - в `work/remove.json` клади только явные запинки (внутри длинного слова или между словами); протяжный конец обычного слова не трогай — иначе съешь букву.
   - Слово длиной 2–4 с — распознавание часто ставит его НАЧАЛО на паузу/«ээ», а само слово звучит в конце (так выпало «физиологиялық»). Посмотри громкость по 0,1 с (`ffmpeg … -f s16le` + numpy): ровный звук на одной высоте = «ээ», тишина = пауза, громкая речь = слово; поставь слову правильные s/e в `work/words.json`.
   - Проверь, что первый проход не пропустил речь: слова второго прохода, попавшие в «паузы» первого (так терялось «Алла Тағала солай жаратқан ғой»), — продли соседнее слово.
4. **Нарезка + зум.** (с `--remove work/remove.json`, если есть запинки) `python3 scripts/cut_text.py media/src.mp4 work/words.json --keep 391-396 --keep 397-412 …`
   - слова берутся целиком, запас 0.16 с, паузы короче 0.4 с не режутся — речь не «сжатая», эксперт договаривает слова полностью («терапия» не «терапи»). Если пользователь жалуется, что съедены буквы, — увеличь `--pad`;
   - планы чередуются: обычный / приближение ×1.13 (зум на склейке прячет джамп-кат);
   - цвет и качество НЕ трогаем (без grade.txt и beauty.py), если пользователь не попросит.
   - Нужна проверка — сделай быстрый превью 540p (`ffmpeg -vf scale=540:-2 -crf 30 -preset ultrafast`) и пришли его, финал — после «ок».
5. **Субтитры** по одному слову, строчными, без знаков — ТОЛЬКО по тексту пользователя: `work/groups.json` = `[[первое_слово, последнее_слово, "кусок текста"], …]` → `python3 scripts/subs_from_text.py`.
6. **Заголовки** `work/titles.json` (пример `example_titles.json`):
   - первый — заголовок пользователя, виден с первой секунды до первой мысли (капс 1–3 слова + рукописная строка: «ГАРАНТИЯ» / *бересіз бе?*, «АСТИГМАТИЗМНІҢ» / *4 себебі*, «КЕСАР VS ТАБИҒИ» / *босану*);
   - дальше — только ключевые слова темы (5–8 на минуту): «ЖАУАПКЕРШІЛІК» / *ата-анада*, «ГЕНЕТИКА» / *10–20%*;
   - БЕЗ номеров «1. 2. 3.» перед словами;
   - рукописная строка ≤ 16 символов, иначе вылезает за край.
7. **Вставки** — 2–4 на ролик, 1,9–2,2 с, только в ключевых местах и строго по теме (новорождённый, беременная, врач с ребёнком, ребёнок с телефоном). Mixkit: поиск `https://mixkit.co/free-stock-video/<запрос>/`, скачать `scripts/mixkit.sh <id> <имя>`. Вставки ВСЕГДА вертикально на весь экран, без пустых мест и размытого фона (пользователь не любит «карточки»). Поэтому только 4K (3840×2160): ищи несколько запросов подряд (botox → cosmetologist, face-massage, wrinkles) и бери 4K-клип рядом по смыслу. Если 4K по теме нет — лучше без вставки, ключевое слово остаётся заголовком. Кадрирование `x` (0..1) проверь одним листом кадров. `python3 scripts/inserts.py work/cut.mov work/inserts.json work/bg_v.mov`.
8. **Звуки.** `python3 scripts/sfx.py work/bg_v.mov work/bg.mov` — «вжух» на вставку и смену заголовка, «поп» на рукописную строку, тише голоса эксперта. Музыку не добавлять, если не просят.
9. **Проверка.** `BG=work/bg.mov STYLE=ref_style.html node render_subs.mjs still 1 10 30` → склей кадры в один лист 216 px и посмотри сам: заголовок не на лице, строка не обрезана.
10. **Экспорт.** `BG=work/bg.mov STYLE=ref_style.html OUT=out/<имя>.mp4 node render_subs.mjs` (14 Мбит/с, −14 LUFS). Для GitHub (<90 МБ) пережми: `ffmpeg -i out/x.mp4 -c:v libx264 -profile:v high -crf 18 -preset slow -pix_fmt yuv420p -c:a copy -movflags +faststart output/<имя>.mp4` (~45 МБ на минуту). Пришли файл в чат и запушь `output/`.

## Стиль (в `ref_style.html`)
- Заголовок: Montserrat 800, `rgb(244,229,208)`, по центру, top 250 (над головой), ширина до 940 px (макс. 118 px), тень.
- Рукописная строка: Bad Script, `rgb(255,227,165)`, золотое свечение, наклон −4°, 92–124 px.
- Каждое слово проявляется из размытия 14px→0 за 0,32 с ровно на своём слове; строка — за 0,4 с; уход — 0,2 с.
- Субтитры: Montserrat 700, 62 px, белые с мягкой тенью, top 1320 (уровень груди).

## Правила
- Режем только то, чего нет в тексте пользователя; смысл не меняем, фразы не переставляем.
- Слова эксперта не обрезать; голос интервьюера убирать.
- Спорные медицинские утверждения (например, против прививок) — предупредить пользователя.
- Не запускать два рендера одновременно: на 4 ядрах длинные ролики падают по памяти — `cut_text.py` поэтому читает каждый кусок отдельным входом.
- Исходники не трогать; работа в `work/`, итог в `output/`. В git — только `output/` и сам скилл.
